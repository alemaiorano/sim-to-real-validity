\section{Method Under Test}
The study harness scores each headline with either a demographic persona or a generic reader.
It operates independently of any commercial product. The fixed ten-persona JSON takes inspiration
from Upworthy-era U.S.\ social-media demographics~\citep{holcomb2013newsuse}. These descriptors
do not specify a deterministic behavioral-profile generator or establish representativeness.

\paragraph{Elicitation and aggregation.}
The prompt requests JSON with a \texttt{click\_intent} number in $[0,1]$
(Appendix~\ref{sec:appendix}). Scores are averaged across recorded observations:
\[
\widehat{s}(v)=\frac{1}{|O_v|}\sum_{(i,d)\in O_v}y_{i,d}(v).
\]
With complete draws this equals the mean over personas and draws. With missing draws it can
differ from the supplementary aggregation mean, which weights draw-collapsed personas equally. The supplementary aggregation comparison evaluates these alternative rules.

\paragraph{Sampling and parsing.}
The primary experiment uses temperature $0.8$, three draws per persona and thirty generic-reader
draws per variant, with request seeds recorded for both providers. The supplementary Gemini
comparison uses the same nominal draw allocation. The GPT-4.1 scalar-checkpoint analysis instead
uses three draws per persona versus ten baseline draws; its requests sent no generation seed. Seeds alone do not guarantee identical
provider responses over time.

Supplementary scalars were produced by a permissive parser that could extract a first number,
clamp values, and accept booleans; event frequencies are unknown. The matched-budget collector
accepts only a finite, non-boolean JSON number in range under the exact requested key. Invalid
parses are recorded as terminal missing observations. Configuration hashes and separate protocol
namespaces prevent mixing primary checkpoints with supplementary scores.
