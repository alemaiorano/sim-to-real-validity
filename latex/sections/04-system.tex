\section{Method Under Test}
\label{sec:system}
The study harness scores each headline with either a demographic persona or a generic reader.
It operates independently of any commercial product. The fixed ten-persona JSON takes inspiration
from Upworthy-era U.S.\ social-media demographics~\citep{holcomb2013newsuse}. These descriptors
do not specify a deterministic behavioral-profile generator or establish representativeness.

\paragraph{Elicitation and aggregation.}
The prompt requests JSON with a \texttt{click\_intent} number in $[0,1]$
(Appendix~\ref{sec:appendix}). The primary collector averages recorded observations:
\[
\widehat{s}(v)=\frac{1}{|O_v|}\sum_{(i,d)\in O_v}y_{i,d}(v).
\]
With complete draws this equals the mean over personas and draws. With missing draws it can
differ from the historical H5 mean, which weights draw-collapsed personas equally. H5 already
evaluated alternative aggregations; they were not wholly left to future work.

\paragraph{Sampling and parsing.}
The main Gemini configuration uses temperature $0.8$, three draws per persona and thirty generic
baseline draws per variant. GPT-4.1 instead uses three draws per persona versus ten baseline draws.
Gemini forwards generation seeds; the GPT runner sends none. Seeds alone cannot guarantee identical
provider responses over time.

The legacy parser could extract a first number, clamp values, and accept booleans. Invalid parsing
could terminate without retry. Historical event frequencies are unknown. The revised collector
accepts only a finite, non-boolean JSON number in range under the exact requested key. Invalid
parses are recorded as terminal missing observations. Configuration hashes and a new protocol
namespace prevent mixing new checkpoints with legacy scores.
